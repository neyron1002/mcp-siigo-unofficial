# Refined prompt v1 — direct download links per operating system

Raw prompt: `2026.11.19_raw_download_links.md`.
Status: **waiting for the owner's OK.**

## 1. Request

Users can't find the install files. Put a direct download link for each operating system in the README and in the release notes. Explain how first.

## 2. Today

- README (EN and ES): one link to the latest release page; the user must find the right file among 11 (3 apps, checksums, signature, 6 size reports).
- Release notes: a table with the file names as plain text, no links.
- The file names include the version (`MCPSiigoUnofficial-0.2.0-macos-arm64.dmg`), so a permanent "latest" link can't point to them.
- The app's updater looks for exactly these versioned names (`update/assets.py`), so **renaming them would break updates** for every installed copy (v0.1.0 to v0.2.0).

## 3. How (recommended)

GitHub has a permanent link that always serves a file from the newest stable release:
`https://github.com/neyron1002/mcp-siigo-unofficial/releases/latest/download/<file name>`.
It only works when the file name has no version. So:

1. **Release workflow:** also upload a copy of each app file with a fixed name:
   - `MCPSiigoUnofficial-windows-x64.exe`
   - `MCPSiigoUnofficial-macos-arm64.dmg`
   - `mcp-siigo-unofficial-linux-x64`
   The versioned files stay, so the updater keeps working. Same bytes, so `SHA256SUMS` also lists the copies.
2. **README (EN and ES):** a "Download" table at the top with one link per system (the permanent links above), the minimum system, and a link to the install guide. `docs/install.md` gets the same table.
3. **Release notes:** the file names become direct links to that release's files.
4. **Now, without a new version:** upload the fixed-name copies to the existing `v0.2.0` release and edit its notes, so the links work today. The next release does it automatically.

Alternatives considered:
- Rename the files: breaks the updater for installed copies. Rejected.
- The workflow edits the README after each release: a bot commit to `main` on every release. More moving parts.
- A download page that detects the visitor's system: nicer, but a new website (GitHub Pages). Later, if wanted.

Cost: release storage only (each release holds the 3 files twice, about 140 MB more). The app download size doesn't change. No new dependency.
