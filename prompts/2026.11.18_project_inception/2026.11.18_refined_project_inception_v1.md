## 1. Goal

Build **MCP Siigo Unofficial**, a free, open-source desktop application. It exposes the Siigo REST API (the web API of Siigo S.A.S., a Colombian accounting and electronic-invoicing software company) as an MCP server. MCP means Model Context Protocol, the open standard that lets AI assistants such as Claude call external tools.

This is a personal portfolio project. It shows the author's skills as a forward deployed engineer, software developer and AI orchestrator. It is **not** an official Siigo product, it costs nothing, and it comes with **no warranty**.

## 2. Functional requirements

1. **MCP server.** The app wraps the Siigo REST API endpoints as MCP tools that AI clients can call (open: D4 transport, D15 tool scope).
2. **System tray icon.** While the app runs, it shows an icon in the notification area: the system tray on Windows, the menu bar on macOS, and the top bar on Ubuntu through AppIndicator, the Ubuntu tray-icon extension. The icon menu has: status, Settings (Siigo credentials), Check for updates, Start at login (on/off), About, Quit.
3. **Start at login.** The app starts automatically when the user logs in to the operating system (open: D16).
4. **Credential storage.** The Siigo credentials and the access token are stored in a local SQLite database, encrypted at rest (open: D6, D7).
5. **Auto-update from GitHub Releases.** The app checks GitHub Releases for a newer version. A small separate updater program downloads the new build, verifies it, replaces the installed files, and restarts the app (open: D10, D11, D12).
6. **Portable.** The app is distributed as a self-contained build. The user does not need Python or any installer (open: D8, D9).
7. **Minimal Qt user interface.** The UI uses Qt with free (LGPL or GPL) components only. Qt is the cross-platform user-interface toolkit. The UI has three parts: a credentials dialog, an About window, and the tray menu. The About window shows the author's name, a short professional summary, a LinkedIn link, and the disclaimer (open: D5, Q1–Q3).

## 3. Platforms (MVP, meaning minimum viable product)

## 4. Repository and process

- GitHub repository under the account `neyron1002` (open: D1 name and visibility, D2 license).
- `prompts/` folder at the repository root. It has one subfolder per working session, named `YYYY.MM.DD_topic_in_snake_case`. Each subfolder holds the raw dictated prompts and their refined versions, named `YYYY.MM.DD_raw_<topic>.md` and `YYYY.MM.DD_refined_<topic>_vN.md` (open: D3 date format).
- The work is iterative. Claude refines the plan → the owner answers the decisions → Claude updates the refined prompt → the owner approves → Claude implements.
- Builds and releases run in GitHub Actions, the free continuous-integration service of GitHub. Each operating system is built on its own runner.
