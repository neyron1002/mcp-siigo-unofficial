## 1. Goal

**MCP Siigo Unofficial** is a free, open-source desktop application. It connects AI assistants (Claude, Codex, GitHub Copilot, and Gemini) to the Siigo REST API through MCP. Siigo S.A.S. is a Colombian company that makes accounting and electronic-invoicing software. MCP means Model Context Protocol.

Who it is for: business owners who are friends of the author, and anyone else who needs it. It is free, comes with no warranty, and is not affiliated with Siigo S.A.S. It is also the author's portfolio piece for forward deployed engineering and AI orchestration.

## 3. Single-file distribution design (D8 + D12)

One file per operating system is attached to each GitHub Release:

| OS | File | What the user does |
|---|---|---|
| Windows | `MCPSiigoUnofficial-<ver>-windows-x64.exe` | Double-click. On the first run, SmartScreen shows "More info → Run anyway". |
| macOS | `MCPSiigoUnofficial-<ver>-macos-arm64.zip` (P5) | Safari unzips it into one `.app`. The user double-clicks it, then confirms "Open Anyway" in System Settings → Privacy & Security on the first run. |
| Ubuntu | `mcp-siigo-unofficial-<ver>-linux-x64` | Right-click → Properties → "Executable as program" (browsers remove that permission), then double-click. |

The file is a small **launcher** (Python frozen with PyInstaller, no Qt). It carries the full app as an embedded, compressed payload. Its modes:

- **Default (double-click):** if this version is not installed yet, it extracts the payload to `<user data>/versions/<ver>/`, copies itself to `<user data>/launcher`, writes the `current` pointer, registers start at login (pointing to the installed launcher), and starts the app. If this version is already installed, it only starts the app, or brings the running app forward.
- **`--run`:** used by start at login. Starts the `current` version directly, with no extraction, so it is fast.
- **`--stdio`:** starts the current version as a stdio MCP server, for clients that launch the server themselves (Claude Desktop).
- **`--update --wait-pid <pid>`:** waits for the old app to exit, extracts the new version beside the old one, runs `--selftest` on it, switches `current`, and starts it. If the self-test fails, it keeps the old version (rollback). It always keeps the previous version and deletes older ones.
- **`--uninstall`:** removes start at login, the versions, and (after confirmation) the data.

Per-user folders, with no administrator rights: Windows `%LOCALAPPDATA%\MCPSiigoUnofficial\`, macOS `~/Library/Application Support/MCPSiigoUnofficial/`, Ubuntu `~/.local/share/mcp-siigo-unofficial/`. On macOS, the launcher also copies the `.app` to `~/Applications/` and removes the quarantine flag from its own copy, so start at login keeps working.

Build: (1) PyInstaller one-folder build of the app → (2) zip + manifest (version, SHA-256) → (3) PyInstaller build of the launcher with the payload inside → (4) `SHA256SUMS` signed with Ed25519. GitHub Actions builds every operating system on its own runner. The PyInstaller bootloader is compiled from source in CI, which reduces antivirus false positives.

## 4. Architecture

```
src/mcp_siigo_unofficial/
  launcher/   single-file installer, runner and updater (no Qt)
  app/        Qt tray icon, Settings dialog, About window, notifications
  server/     MCP server (official `mcp` Python SDK): Streamable HTTP + stdio
  siigo/      Siigo REST client (httpx): auth, token renewal, retries, 429 back-off
  vault/      SQLite (WAL mode) + AES-256-GCM + keyring master key
  autostart/  Windows Run key, macOS LaunchAgent, Ubuntu ~/.config/autostart
  update/     GitHub Releases check, download, signature verification
  i18n/       English and Spanish strings
tests/        unit tests + mock Siigo server
references/   reference material (third-party code is git-ignored; only our notes are committed)
prompts/      raw and refined prompts per session
```

Runtime: one process. Qt runs on the main thread; the MCP HTTP server runs on a background thread (uvicorn on `127.0.0.1`, path `/mcp`), protected by a random bearer key stored in the vault. Tray menu: status, "Copy client setup" (per client: Claude Code, Claude Desktop, Codex, GitHub Copilot in VS Code, Gemini CLI), Settings, Start at login, Check for updates, About, Quit.

## 5. MCP tools (D15: full read and write)

The final list is confirmed against the Siigo developer documentation in phase 1. It covers:

- **Catalogs (read):** document types, taxes, payment types, cost centers, users/sellers, warehouses, price lists, account groups.
- **Customers and products:** list, get, create, update.
- **Invoices:** list, get, create, PDF, XML.
- **Credit notes, cash receipts (vouchers), and journals:** list, get, create.

Read tools have `readOnlyHint`. Create and update tools have `destructiveHint`. All tools return compact JSON and clear error messages.

### 5.1 Write actions switch and safety (owner requirement, v3)

1. **Switch.** "Write actions: ON/OFF" appears in the tray menu and in Settings. The state is stored in the vault. The default and its behavior after a restart are decided in P9.
2. **Warning when turning it on.** A modal dialog (a window that must be answered before anything else) explains the risks: real records are created in Siigo, and invoices go to the DIAN, Colombia's tax authority. It states that the MCP is only a bridge to the Siigo API, and that the user is fully responsible for every action their AI client executes. The software is free, has no warranty, and its author is not responsible for AI decisions or executions. The user must tick "I understand and accept responsibility" before the "Enable write actions" button activates. The acceptance (date and time, app version) is recorded in the vault and in the log.
3. **Tray icon changes.** While writes are on, the tray icon shows a red warning badge, and the tooltip says "WRITE ACTIONS ENABLED". A system notification appears when the switch turns on. Another appears when it turns off.
4. **When writes are off:** write tools are not listed to AI clients. The server instructions tell the AI that writes are disabled and that only the user can enable them from the tray. The server sends `notifications/tools/list_changed` (the MCP message that tells clients the tool list changed) every time the switch changes.
5. **Warning to the AI before each write (P10).** Every write tool description starts with a "⚠ WRITE ACTION — REAL DATA IN SIIGO" block. The block tells the model to explain the action to the user and to get the user's explicit authorization first. The server also enforces this itself, without relying on the model:
   - If the client supports MCP **elicitation** (the MCP feature that lets a server ask the user a question directly in the client's interface), the server shows the user a summary of the action and asks Approve or Reject. Only Approve continues.
   - Otherwise, a **two-step confirmation** applies. The first call only returns a preview, the warning text, and a one-time `confirmation_id` that expires after 5 minutes. The model must show the preview to the user and call again with that id. The server rejects a write without a valid id.
6. **Liability statement.** The same text appears in the enable dialog, the About window, the README (English and Spanish), and the server instructions. The MIT license already excludes warranty and liability.
