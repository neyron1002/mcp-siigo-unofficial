## Phase 11 · branch `phase-11-write-risk-levels`

- `server/catalog.py`: `Risk` (`change`, `outbound`, `permanent`) with `allows_shortcuts`, `needs_window`, `parse` (unknown values are `permanent`), and `strictest`. Every write tool in `catalog.json` has a `risk`; `scripts/build_catalog.py` has a `RISK` map (empty until phase 13). `risk_of(tool)` gives the shipped level (unknown tools are `permanent`).
- `server/approval.py`: `ApprovalRequest.risk`. The broker never pre-approves `outbound` or `permanent` writes (no automatic approval, no grant, and no write used up). "Approve similar" on a risky write approves that one request and starts no grant. `from_json` (the stdio → tray route) takes the strictest of the request's level and the tray's own catalog, so a request can't lower it. `summarize(..., full=True)` keeps outbound fields whole.
- `server/app.py`: permanent writes skip the AI app's question in "In the AI app" mode and go to the Siigo window. Outbound writes show the whole body and an "outside Siigo" line in the AI app's question. The tool descriptions of risky writes start with a PERMANENT or SENDS DATA OUTSIDE SIIGO block.
- Approval window: a red banner (can't be undone) or an amber banner (sends data outside Siigo); for risky writes the "Approve similar writes" button is hidden and disabled, and a line says these are approved one at a time. EN/ES strings.
- CLAUDE.md rule 3 and plan v8 section 5.1 record the rule (owner decisions A2–A4; stricter only).
- Docs: usage, "Risky writes".
- **Deviation:** reading the record before a delete or annul, so the window shows its name, number, customer, and total, moved to phase 13, where the tools that need it are added.
- Tests use a sample catalog with one permanent and one outbound tool, because the shipped catalog has none yet.
