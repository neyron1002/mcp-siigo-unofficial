## 2. stdio vs HTTP (facts used for Q2)

| Topic | stdio | HTTP |
|---|---|---|
| Who starts the server | Each AI session starts `<launcher> --stdio` | One server inside the tray app, `127.0.0.1:39217` |
| Supported by | Claude Code, Claude Desktop chat, Codex, Gemini CLI, VS Code | Claude Code, Gemini CLI, VS Code, Codex (recent versions, to check). **Not Claude Desktop chat** through its settings file |
| Key in AI app files | None | Bearer key |
| Tray app needed | Only for writes (writes turn off when it quits) | Always |
| Memory | About 78 MB per process (measured in the dev setup on 2026-11-19) | One shared process |
| Start | About 0.5 s per session (dev measurement) | Already running |
| Siigo login | One per process today (token kept in memory only) | One shared |
| Approval window | Through the local channel to the tray app | Direct |
| Updates | Sessions keep the old version until restart; on Windows the old version is deleted later | Updated when the tray app restarts |

## 3. Plan

- Detection, user-level connect, disconnect, and repair for Claude Code, Claude Desktop, Codex, Gemini CLI, and VS Code (Q7). The app's own `mcp add` command first, a safe file edit otherwise (Q5). Backups, atomic writes, no overwrite of broken files, and a name-conflict check (Q11).
- stdio by default (Q2). HTTP per app under Advanced (Q2b). The HTTP server keeps running (Q2c). Setups made by hand show "Connected · HTTP" with a "Switch to stdio" button (Q2d). The Siigo token is shared through the encrypted vault (Q2e).
- The Connect window opens on first start and once after the update (Q12), and from the tray menu. A notification asks when a new app is found (Q4). Restart Claude Desktop button (Q6). Uninstall disconnects (Q13). Our own entry is repaired automatically after the app moves (Q14).
- Phases 7 (installer), 8 (window), 9 (docs and `v0.2.0-rc.1`), then the owner's Mac test, then `v0.2.0`.
