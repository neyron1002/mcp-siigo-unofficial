# Refined prompt v1 — one-click connection to AI apps (plan and decisions)

Raw prompt: `2026.11.19_raw_one_click_client_install.md`. Status: **draft, waiting for the owner's decisions (section 6)**.

## 1. Refined request

The app works on the owner's Mac (v0.1.0). Connecting it to an AI app is still technical: the user copies a text from the tray menu and pastes it into a terminal or a config file. Make this a single click for people with no technical knowledge:

1. The app **detects** which AI apps are installed for this user: Claude Code (terminal), Claude Code inside the Claude Desktop app, Claude Desktop (chat), Codex, and Gemini CLI.
2. It offers a **"Connect AI apps"** button. One click adds the Siigo MCP (Model Context Protocol) server to every detected app, at **user level**, so it works in every project and every new session of that user.
3. The user can **undo** it with one click, too.
4. Find out whether "the cloud" can make this easier, and say what is possible.
5. Save the prompt, refine it, write the plan, list the decisions with recommendations, and wait for the owner's answers before building.

## 2. What "cloud" means here, and the limit

There are two different things:

- **Claude Code inside the Claude Desktop app, on your computer** ("Code" tab, local sessions). It runs on your Mac and reads the same user settings as Claude Code in the terminal. A local install reaches it. **In scope.**
- **Cloud sessions** (Claude Code on the web, or cloud sessions started from the Desktop or mobile apps). They run on Anthropic's servers, not on your computer. They **cannot** reach a server at `127.0.0.1` on your Mac. To use Siigo there, the server must be on the public internet with HTTPS (Hypertext Transfer Protocol Secure) and OAuth (an open standard for sign-in), and your Siigo credentials would leave your computer. That changes the security design of the whole project (hard rules 3 and 4). See decision **Q1**.

## 3. Proposed design (local, one click)

### 3.1 Detection (no admin rights needed)

| App | Detected by | Where the server is added (user level) |
|---|---|---|
| Claude Code (terminal and Desktop "Code" tab) | `claude` command found, or `~/.claude.json` / `~/.claude/` exists | `claude mcp add --scope user …` when the command is found; otherwise a safe edit of `~/.claude.json` |
| Claude Desktop (chat) | macOS: `/Applications/Claude.app` or `~/Library/Application Support/Claude/`; Windows: `%APPDATA%\Claude\` (there is no official Linux app) | `claude_desktop_config.json` → `mcpServers.siigo` |
| Codex (CLI, desktop app, and IDE extension share one config) | `codex` command, or `~/.codex/` exists | `codex mcp add …` when found; otherwise `~/.codex/config.toml` → `[mcp_servers.siigo]` |
| Gemini CLI | `gemini` command, or `~/.gemini/` exists | `gemini mcp add --scope user …` when found; otherwise `~/.gemini/settings.json` |
| GitHub Copilot in VS Code (optional, Q7) | `code` command, or the VS Code user folder exists | `code --add-mcp …` (user profile) |

GUI apps on macOS do not get the terminal's `PATH`, so the app looks for the commands in the user's login shell and in the usual folders (`~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`, the npm global folder).

### 3.2 Connection type: stdio for every app (Q2)

Every app starts the installed launcher with `--stdio`. Reasons:

- No private key is written into any config file (the HTTP setup puts the bearer key in the file).
- No port, no firewall prompt, and it works even when the tray app is closed. When the tray app is closed, write actions stay off (safe default, rule 3 unchanged).
- The launcher path stays the same after updates, so updates don't break the connection.

The "Copy client setup" menu stays for advanced users who want HTTP.

### 3.3 Safe file edits

- Read, merge, and write back only the `siigo` entry. Never remove or change other servers or settings.
- Before the first change to a file: a backup next to it (`<file>.siigo-backup-<date>`).
- Atomic write (write a temporary file, then rename), keep the file's permissions.
- If the file is not valid JSON or TOML (Tom's Obvious Minimal Language), stop and tell the user; never overwrite a broken file.
- An entry named `siigo` that does **not** start our launcher (for example the owner's earlier `mcp_siigo` server) is **not** replaced without asking.
- Codex TOML: read with Python's built-in `tomllib`, add our section as text, and check the result with `tomllib`. **No new runtime dependency** (rule 2).
- No Siigo credentials, tokens, or keys go into any client file (rule 4).

### 3.4 User interface

- **First start**, after the welcome: a "Connect your AI apps" window. It lists the detected apps with checkboxes (all checked), the ones not found (greyed out), and one button: **Connect**. A "Not now" button closes it.
- **Tray menu:** "Connect AI apps…" opens the same window. It also shows the state of each app (connected / not connected / not found) and a **Disconnect** button.
- After connecting: "Done. Restart Claude Desktop to see the Siigo tools," with a **Restart Claude Desktop** button (Q6). Terminal apps only need a new session.
- **Later detection (Q4):** when a new AI app appears (checked at start and every few hours), a notification asks "Codex found. Connect it to Siigo?". Nothing changes without a click.
- All texts in English and Spanish.
- Command line for scripts and CI (continuous integration): `--connect-clients [--client NAME]`, `--disconnect-clients`, `--list-clients`.

### 3.5 Tests

- Unit tests with a fake home folder on Windows, macOS, and Ubuntu: detection, merge with existing servers, backup, broken file, name conflict, disconnect, and idempotence (running twice changes nothing).
- CLI paths tested with fake `claude`, `codex`, and `gemini` commands.
- CI smoke test: install the release file in a temporary home, run `--connect-clients`, check the written files, run `--disconnect-clients`, check they are back to the original.

## 5. What only the owner can check (on the Mac)

1. Update to `v0.2.0-rc.1` (tray → Check for updates; pre-release builds only see pre-releases, so install rc.1 by hand once).
2. Click **Connect AI apps → Connect**.
3. In a new terminal: `claude mcp list` shows `siigo`. In the Claude Desktop app, open a new local Code session and a new chat: both show the Siigo tools. Also check Codex and Gemini if installed.
4. Click **Disconnect** and check that the tools are gone and your other servers are still there.
