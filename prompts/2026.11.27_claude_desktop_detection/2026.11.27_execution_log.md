# Execution log — Claude Desktop detection on Windows (released in v0.3.1)

Branch `fix-claude-desktop-msix`, from `main` 8a485bd on 2026-11-27, rebased on 85f7e9b.

## Cause

"Connect AI apps" did not find Claude Desktop on the owner's Windows 11 PC. Claude Desktop there is the MSIX package (package family `Claude_pzs8sxrjxfjjc`, version 6.28899.6.0); there is no classic install (`%LOCALAPPDATA%\AnthropicClaude`). The app knew only the classic layout, with settings in `%APPDATA%\Claude`. The MSIX package keeps its settings elsewhere:

- older versions: `%LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude\` (Windows redirects the package's `%APPDATA%` there);
- newer versions: `%LOCALAPPDATA%\Claude-Data\claude_<id>\`. On this PC Claude Desktop moved its data there on 2026-11-27 at 15:38 and left only a `.user-data-left.claude_<id>` note in `%APPDATA%\Claude` and in the package's `LocalCache\Roaming\Claude`.

Before the move the app found nothing. After it, `%APPDATA%\Claude` existed (only the note file), so the app showed Claude Desktop as found but would have written a settings file that Claude Desktop does not read. Checked read only; the real settings file was inspected by key names only.

## Changes

- `clients/apps.py` (`ClaudeDesktop`): on Windows the MSIX package folder counts as installed; the settings folder is, in order, `Claude-Data\claude_<id>`, the package's `LocalCache\Roaming\Claude`, then `%APPDATA%\Claude`.
- Tests: detection, connect, and disconnect (other servers and settings kept) for the classic install, the older MSIX layout, and the `Claude-Data` layout; a first connect on a new MSIX install; the Connect window for all three.
- `docs/clients.md`: Windows paths for both install types. `docs/troubleshooting.md`: entry for this problem.

## Verification

- Windows host (owner allowed the project `.venv` again on 2026-11-27): ruff, ruff format, mypy strict clean; 527 passed, 10 skipped (the 2 catalog source tests need `pyyaml`, missing in the older `.venv`; they pass in CI).
- `--list-clients` on this PC: before, `...\Roaming\Claude\claude_desktop_config.json`; after, `...\Local\Claude-Data\claude_pzs8sxrjxfjjc\claude_desktop_config.json`. No real connect was run.

## Release

- PR https://github.com/neyron1002/mcp-siigo-unofficial/pull/31. The first CI run crashed (segmentation fault) in `test_connect_writes_settings_and_shows_restart` on the Linux and macOS runners, twice. The worker thread was writing a file while the main thread crashed in Qt's event loop. Cause: a window from an earlier test was left to Python's garbage collector, which runs on whichever thread is allocating, so it could be freed on the "connect-ai-apps" worker thread; the new tests only moved when the collection ran. Fix: the Connect window tests collect garbage on the GUI thread before and after each test. CI green (7 checks); merged as 1ff34e3.
