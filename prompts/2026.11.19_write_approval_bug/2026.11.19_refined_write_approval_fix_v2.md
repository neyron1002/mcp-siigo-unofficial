## 3. Approval modes (Settings → Write approval)

| Mode | Per write | Works in |
|---|---|---|
| Siigo window (default) | Window: summary, Show details, Approve, Reject, Approve similar writes for 10 minutes | Every AI app |
| Notification first | Notification; a click opens the window; it opens by itself after 15 s | Every AI app |
| In the AI app (elicitation) | The AI app's question; a decline in under 1 s is treated as "couldn't ask" and opens the window | Every AI app (with the fallback) |
| Automatic for a time (dangerous) | Nothing until it ends | Every AI app |

Protections for automatic approval: type `APPROVE ALL` to confirm, red tray icon with a countdown, never survives a restart, maximum 100 writes, logged in the event log, and Stop now in the tray menu. Only the user changes the mode, in the app; no MCP tool can change it.

Technical: the HTTP server runs inside the tray app and opens the window directly. A stdio server asks the tray app over a local channel protected by the private key. If the tray app can't be reached, the write is refused. Writes are on only while the tray app runs (quitting resets the switch). No new library is needed: the window and the notification use Qt.
